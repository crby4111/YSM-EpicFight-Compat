# 游戏内帧耗时记录

此工具只记录数据，不自动判定 R07 通过；平时不采样。客户端命令：

```text
/ysmcompat bench start M042-A-1
/ysmcompat bench start M042-B-1 180
/ysmcompat bench status
/ysmcompat bench stop
```

每次先预热 60 秒，再默认采样 180 秒；可指定 30～600 秒。标签只允许字母、数字、下划线、连字符。`stop` 提前终止会将记录标为无效。数据存放在当前游戏实例的 `ysmcompat-acceptance/<标签-随机目录>/frame-times.json`，不会覆盖旧记录或修改规则。

采样期间关闭聊天与菜单，保持同一场景、路线、模型数量和图形设置。开启菜单、暂停、失去世界或加载另一份规则都会使本轮无效；需要查询 status 时应在预热阶段操作。中位数、P95、≥100ms 的帧数和逐帧毫秒数据均保留，不删除慢帧。完成后的结果写盘不计入采样。

记录来自连续客户端渲染 END 事件之间的时间，包含帧等待和客户端调度，不能称为独立 GPU 计时。样本数量不足、内存上限溢出、场景中断及提前结束都会标为无效。`valid: true` 仅表示采样程序接受这份数据，不代表画面、性能、模型数量或完整验收通过。

按验收文件固定实际硬件、依赖、候选 JAR 校验、分辨率、视距、帧率限制、垂直同步和路线；一人及四个可见角色分别测量。A 使用同候选构建且显式 `enabled:false`；B 使用默认 EF 空规则；C 使用已冻结的完整规则。每组各做三轮，保留全部原始记录，比较逐轮结果与各组中位汇总；不挑选最有利的一轮。检查绝对帧耗时与慢帧，再核对中位帧耗时增加 ≤10%、P95 增加 ≤15%。

复杂模型 CPU 蒙皮、冷加载与资源重载另做记录，不能用普通模型的稳态数据替代。若设置或路径发生变化，即使工具未能自动发现，也必须将本轮登记为无效。真实游戏未运行前，没有 R07 测量结果。
