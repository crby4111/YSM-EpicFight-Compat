# 外部动作预览器（Minecraft 1.20.1 开发工具）

双击本目录的 **启动预览器.cmd**。它打开本机浏览器窗口，使用当前源码编译出的计算组件，不启动 Minecraft。

可选择模型控制器及支持的原生脚本槽位，设置运动与转身输入，或导入 F9 问题记录查看采集帧。
配置方法和支持范围见 [控制器规则说明](CONTROLLER_RULES.md)。

初次使用需要 Python 3、Java 21 构建进程和 Java 17 工具链；先在仓库根目录运行 `gradlew prepareMotionPreview`。移动工作区或 Java 后，需要重新运行准备任务，更新 `build/motion-preview/runtime.json` 中的路径。

## 操作

1. 模型库目录选择 `yes_steve_model`，其下应有 `builtin`、`custom` 或 `auth`。初次默认显示工具自带的原创方块示例。
2. 选择模型和贴图，再选择 EF 动作。支持搜索、播放、暂停、逐帧和拖动时间；两个窗口共用相机与时间。
3. 左侧为 EF 基础姿态（保留模型外观）；右侧可以切换为当前动作规则、指定模型片段或相同 EF 基础姿态。
4. 移动、攻击、受伤、使用物品、主手物品 ID、战斗模式、头部俯仰和偏转均为可控输入，用于验证条件匹配。
5. 载入或编辑 `motion_rules.json` 后重建。规则修改只在此窗口中生效，可以导出为文件，不会写回游戏配置。
6. 自定义资源包动作可以选择命名空间后载入 Bedrock 动画 JSON。例如命名空间 `motion_demo` 和片段键 `cape_swing` 对应规则中的 `motion_demo:cape_swing`。已内置上一版的 `ysm_epicfight_compat:example_cape_swing`。
7. 在“运动与转身输入”中设置转身速度及三轴速度。每次重建从独立的物理状态开始。
8. 选择对应模型后，点击“查看 F9 问题记录”并选择 `issue.json`。骨架、绑定和缩放匹配后，右侧直接显示记录的模型蒙皮帧，左侧重建记录的 EF 输入。记录帧不重新推进动画或物理，不能作为完整游戏回放。

鼠标拖动旋转，滚轮缩放，Shift + 拖动平移；也可使用正面、侧面、背面和适合窗口按钮。骨骼连接为辅助检查层。

## 与模组的关系

- 实际使用 `LocalModelRepository`、`SkinMeshCompiler`、`ParallelAnimationProgram` 与 `AuxiliaryPoseMatrices`。没有另写一套近似动作规则。
- EF 动作采样来自当前开发依赖中的实际 biped 动作文件；数据文件与 POV 专用动作不作为第三人称动作列出。
- 对源文件只读；示例、日志、编译组件和临时数据写入仓库 `build/motion-preview`。不复制或分发用户模型，不携带 Minecraft 或官方 YSM jar。
- 预览器仅监听本机地址，页面和依赖均从本机读取，不使用在线 CDN。
- 原创示例包含披风与尾巴片段，可用“示例：叠加披风与尾巴”验证额外动作与 EF 并行。

## 边界

这是受控输入下的离线姿态重建，尚不等同于游戏最终画面。完整原生控制器、武器本体、光照、粒子、音效、服务器事件、碰撞与第一人称最终视图未重建。查询或函数未实现时会列出名称；不能以默认零值推断已经兼容。

当前模型最多 4096 个骨骼；超过上限明确失败。大模型的预览采样率会按数据量降低，确保一次姿态数据有界。模组中大于 EF GPU 调色板容量的模型使用现有 CPU 蒙皮路径，游戏内性能仍需实测。

模型包的可读性遵循现有官方 YSM 加载器；需要官方运行环境才能读取的包会明确报错。请选择已有可读模型目录，不要把 `.ysm` 后缀改成 JSON。

## 开发验证

```powershell
gradlew prepareMotionPreview test
python src/preview/test_preview.py
```

Python 检查直接调用真实 Java 计算进程，涵盖目录发现、网格/贴图、两侧相同 EF 结果、模型片段覆盖、自定义额外片段、错误输入与资源上限。源码更新后重新准备组件并重启预览器，避免继续使用旧计算进程。
